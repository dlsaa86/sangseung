# goal — 목표 하나를 끝까지 끌고 가는 레일

## 이 스킬이 막으려는 실패

**① 팀이 파일로만 존재한다.**
2026-08-07 에 `production/session-logs/agent-audit.log` 를 셌다. 4일간 서브에이전트
호출 **48회**, 그중 **8종**만 돌았다. 46개 중 38개는 **한 번도 안 돌았고**, 거기엔
`game-designer`·`systems-designer`·`economy-designer`·`qa-lead`·`art-director`·
`test-adversary` 가 전부 포함돼 있었다. 판단은 전부 메인 루프가 혼자 했다.

돈 둘의 공통점이 답이다 — `unity-scene-owner`(13회)는 CLAUDE.md 가 배타 소유권으로
**강제**했고, `visual-critic`(9회)은 `visual-verify` 스킬이 **직접 불렀다**.

> 호출 장치가 없는 에이전트는 에이전트가 아니라 문서다.

그래서 이 스킬의 2·4단계는 **권장이 아니라 호출**이다. "필요하면 부르세요"라고 쓰는
순간 39번째 안 돌아가는 파일이 된다.

**② 애매한 목표를 조용히 삼킨다.**
CLAUDE.md §5 「되돌릴 수 있는 결정은 질문하지 않고 기본값으로 진행한다」는
**자율주행용 규칙인데 모드 구분 없이 항상 로드된다.** 그래서 협업 중에도 모호한 지시가
되물어지지 않고 기본값으로 흡수됐고, 그 잔해가 `PENDING_DECISIONS.md` 의 PD-01~35 다.

**③ 완료를 아무도 대조하지 않는다.**
`autonomous-batch-gate.sh` 는 `review-mode=solo` 에서만 돈다. CLAUDE.md 가 직접
인정하는 대로 *"협업 모드에서는 여전히 아무것도 강제하지 않는다 — 대조하지 않으면
그냥 통과한다."* 사용자가 자리에 있는 동안 던진 목표는 지금까지 무보증이었다.

## 우선순위 — CLAUDE.md §5 와의 관계

충돌처럼 보이지만 적용 시점이 다르다.

| | 적용 시점 | 규칙 |
|---|---|---|
| **이 스킬 1단계** | 목표 **진입 시** | 완료 기준이 안 잡히면 되묻는다. 착수 금지 |
| CLAUDE.md §5 | 목표 **진행 중** | 되돌릴 수 있는 판단은 묻지 말고 기본값 + ASSUMPTION_LOG |

즉 **입구에서 한 번 세게 묻고, 들어온 뒤에는 안 묻는다.** 진행 중에 매번 묻는 것은
§5 위반이고, 입구에서도 안 묻는 것은 이 스킬의 존재 이유를 없앤다.

## 쓰지 않는 경우

- 한 줄 질문, 상태 확인, 잡담
- 오타·컴파일 에러 같은 단발 수정 → 그냥 고친다
- 이미 `/dev-story` 로 진행 중인 Story → 그 레일을 계속 쓴다
- 탐색만 필요한 경우 → `Explore` 또는 `/project-stage-detect`

## 0단계 — 활성 목표 확인

```bash
ROOT="${CLAUDE_PROJECT_DIR:-$(pwd)}"
ls "$ROOT/production/goals/ACTIVE.md" 2>/dev/null && cat "$ROOT/production/goals/ACTIVE.md"
```

**이미 ACTIVE 목표가 있으면 두 번째를 열지 않는다.** 사용자에게 알리고 고르게 한다 —
이어서 진행할지, 접고 새 목표로 갈지. 목표 둘을 동시에 여는 순간 완주 판정이 무의미해진다.

접을 때는 `production/goals/<slug>-<날짜>.md` 로 옮기고 `ACTIVE.md` 를 지운다.

## 1단계 — 심문 (착수 금지 구간)

**이 단계에서는 코드·씬·에셋을 한 줄도 건드리지 않는다.** 읽기는 허용된다.

### 먼저 읽는다

CLAUDE.md 「문서 권한과 시작 순서」대로. 목표와 관련된 절만 읽으면 된다 —
전문 통독은 낭비다.

`docs/MASTER_PRD.md` → `TECH_SPEC.md` → `CURRENT_PHASE.md` → `VISUAL_SPEC.md` →
`DECISION_LOG.md` → `docs/TOPDOWN_MASTER_BACKLOG.md`(해당 항목)

### 그다음 되묻는다 — 최소 3개, 최대 5개

`AskUserQuestion` 으로 한 번에 묻는다. 아래 다섯 축에서 **실제로 답이 갈리는 것만**
고른다. 이미 문서에 답이 있는 것을 묻는 것은 심문이 아니라 게으름이다.

| 축 | 묻는 것 | 안 물으면 생기는 일 |
|---|---|---|
| **완료** | 무엇이 되면 끝인가. 어떤 화면·수치·동작으로 확인하나 | 영원히 안 끝나거나 아무 때나 끝난다 |
| **범위 밖** | 이번에 **안** 하는 것은 무엇인가 | 범위가 조용히 부풀어 3배가 된다 |
| **판정자** | 누가 어떻게 합격을 판정하나 | 구현자가 자기 걸 승인한다 |
| **되돌리기** | 되돌리기 어려운 결정이 섞여 있나 | 나중에 못 되돌린다 |
| **충돌** | 기존 PRD·DECISION_LOG 와 어긋나는 지점이 있나 | 동결 명세와 다른 게 만들어진다 |

**충돌을 발견하면 그것을 먼저 지적한다.** 사용자 지시가 `DECISION_LOG.md` 의 확정
결정과 어긋나면, 순순히 따르지 말고 어긋난다는 사실과 양쪽 선택지를 제시한다.
사용자가 재확인하면 그건 결정이므로 그대로 진행하고 `DECISION_LOG.md` 에 변경으로 적는다.

### 그리고 목표 파일을 쓴다

사용자 답을 받은 뒤 `production/goals/ACTIVE.md` 를 만든다. **아직 `status: INTAKE` 다.**

```markdown
# GOAL: <한 줄 제목>
- slug: <kebab-case>
- status: INTAKE
- opened: <YYYY-MM-DD>
- branch: <현재 브랜치>

## 배경
<왜 하는가. 관련 PRD 절·백로그 항목 번호>

## 범위 밖
- <이번에 하지 않는 것>

## 완료 기준
- [ ] AC-1 <관측 가능한 것. "잘 동작한다"가 아니라 "10층까지 진행 시 콘솔 오류 0">
- [ ] AC-2 ...
- [ ] VERIFY-1 <독립 검증자>가 이 목표를 검토하고 판정을 기록했다
- [ ] VERIFY-2 컴파일 통과 + Ascend/Run Self Tests 결과가 기록됐다

## 편성
<2단계에서 채운다>

## 검증 기록
<4단계에서 채운다>
```

**`VERIFY-` 두 줄은 항상 넣는다.** 완주 게이트는 체크박스만 보므로, 독립 검증 강제는
이 두 줄로 성립한다. 지우면 자기 승인이 다시 열린다.

AC 는 **관측 가능해야 한다.** "밸런스가 좋아진다"는 AC 가 아니다.
"시드 300 × 정책 3종에서 승률 편차 15%p 이내"가 AC 다.

### 승인을 받는다

목표 파일을 사용자에게 보이고 **명시적 동의를 받는다.** 동의 후에만
`status: ACTIVE` 로 바꾼다. 이 순간부터 완주 게이트가 작동한다.

> ⚠ `INTAKE` 상태에서는 게이트가 돌지 않는다. 사용자 답을 기다리며 멈추는 것은
> 정상이고, 그 멈춤까지 막으면 심문 자체가 불가능해지기 때문이다.

## 2단계 — 편성 (호출한다, 추천하지 않는다)

`producer` 에이전트를 **실제로 호출**해서 이 목표에 필요한 역할을 고르게 한다.

```
Agent(subagent_type: "producer",
      prompt: "목표: production/goals/ACTIVE.md 를 읽어라. 이 목표를 완수하는 데
               필요한 역할을 .claude/agents/ 의 46개 중에서 고르고, 각자에게 줄
               작업과 인계 순서를 정하라. 씬·프리팹·머티리얼 수정은 unity-scene-owner
               만 가능하다는 제약을 지켜라. 역할별로 '무엇을 산출하는가'를 한 줄씩 적어라.")
```

producer 의 답을 목표 파일 `## 편성` 절에 적는다. 그 뒤 아래 표로 **누락을 보정한다** —
producer 가 빠뜨리기 쉬운 자리가 있다.

| 목표가 이것을 건드리면 | 반드시 넣는 역할 |
|---|---|
| 새 게임 규칙·시스템 | `game-designer` → `systems-designer` |
| 수치·확률·경제·진행 곡선 | `economy-designer` (+ `tools/headless` 스윕) |
| 화면에 보이는 것 | `art-director` → `unity-scene-owner` → `visual-critic` |
| UI·조작 흐름 | `ux-designer` → `unity-ui-specialist` |
| 코드 구조가 바뀜 | `lead-programmer` 또는 `technical-director` |
| 씬·프리팹·머티리얼 | `unity-scene-owner` **단독** — 다른 누구도 안 된다 |
| 서사·대사 | `narrative-director` → `writer` |

### 병렬 규칙

CLAUDE.md 「에이전트 소유권 규칙」이 그대로 적용된다. 어기면 머지가 깨지는 게 아니라
**조용히 손상된다.**

- 디렉터리 배타 소유가 지켜지는 조합만 동시에 띄운다
- **`.unity`/`.prefab`/`.mat`/`.asset` 작업은 절대 병렬로 돌리지 않는다**
- 씬을 여는 에이전트는 언제나 한 명

## 3단계 — 구현

편성된 순서대로 진행한다. 기존 스킬이 있으면 그것을 쓴다 —
`/create-stories`, `/dev-story`, `/quick-design`, `/balance-check`.

지키는 것:

- **컴파일을 깨뜨린 채 다음으로 가지 않는다.** asmdef 이 없어 하나가 전체를 막는다.
  `.cs` 를 고쳤으면 첫 검증은 언제나 `grep -an "error CS" Logs/Editor.log | tail -5`
- 되돌릴 수 있는 판단은 묻지 말고 기본값 + `docs/ASSUMPTION_LOG.md`
- 되돌리기 어려운 것만 `docs/runtime/PENDING_DECISIONS.md` 로 올리고 **멈추지 않는다**
- AC 를 하나 충족할 때마다 목표 파일에서 `- [ ]` → `- [x]` 로 바꾸고 **근거를 덧붙인다**

```markdown
- [x] AC-2 10층 진행 시 콘솔 오류 0
      근거: Logs/Editor.log 20260807_1420 런, error/exception 0건. FloorSessionTests 12/12 통과
```

**근거 없는 체크는 자기 승인이다.** 어떤 파일·테스트·캡처가 그것을 보이는지 적는다.

## 4단계 — 독립 검증 (호출한다)

**구현한 에이전트가 `VERIFY-` 를 체크하지 않는다.** CLAUDE.md 탑다운 규칙 6.

목표 성격에 맞는 검증자를 **실제로 호출**한다. 이들은 전부 읽기 전용이라 병렬로 안전하다.

| 무엇을 검증하나 | 부르는 에이전트 |
|---|---|
| 요구사항 대조 (PRD·백로그와 어긋났나) | `requirements-auditor` |
| 화면에 보이는 것 | `visual-critic` (+ `/visual-verify` 로 캡처 먼저) |
| 경계 조건·반례 | `test-adversary` |
| 구조가 나중에 깨지나 | `architecture-critic` |
| 성능 주장 | `performance-investigator` |

호출할 때 **결론을 알려주지 않는다.** "이거 잘 됐는지 봐줘"가 아니라
"이 목표 파일의 AC 를 실제 구현과 대조하고 어긋난 것을 찾아라"로 준다.

판정을 `## 검증 기록` 절에 그대로 붙인다. **REJECT 를 받았다고 목표를 접지 않는다** —
지적을 AC 로 되돌리고 3단계로 간다. 단 같은 항목에서 **3회 실패하면 4회째를 시도하지
않는다.** 필요한 것은 노력이 아니라 구조 변경이거나 사용자 결정이다.

---

## 5단계 — 마감

AC 가 전부 `- [x]` 가 되면 완주 게이트가 통과시킨다. 그때 한다.

1. 자체 검증 — `Ascend/Run Self Tests`
2. `docs/runtime/TOPDOWN_PROGRESS.md` 갱신 (커밋 전에)
3. 로컬 커밋 — **push·PR·main 병합은 사용자가 명시적으로 요청할 때만**
4. `production/session-logs/` 에 보고서
5. `ACTIVE.md` → `production/goals/<slug>-<날짜>.md` 로 이동
6. 사용자에게 보고 — CLAUDE.md 「완료 보고」 항목대로
