블렌더 `SM_ElevCab_Panel_AD57.blend`에서 작업. **저장 완료.**

| | 이전(원형) | 현재(H안) |
|---|---|---|
| 개구부 | 지름 243mm 원 | **334.4mm 정사각** |
| 베젤 | 57.8mm | **43.5mm** — 아래 디스플레이(게이지)와 동일 |
| 계단 | 림+스텝+필드 3단 | **림+스텝 2단** (게이지와 동일) |
| 내부 공간 | 312×312×**89mm** | **334×334×334mm 정육면체** |
| 코너 나사 | 4개 | **제거** |
| 트라이 | 14,040 | **3,888** |

핵심 근거: 게이지 하우징과 유리의 실측 바운드 차이가 **사방 43.5mm 균일**. 통관을 여기에 맞췄다.
단면 실측(월드 y, 중심에서의 거리 mm):

```
게이지  2.8187 림트레드 189.2~210.8 / 2.8267 스텝트레드 167.7~189.3   => 금속 43.1mm, 2단
통관H   2.8237 림트레드 188.4~210.7 / 2.8348 스텝트레드 167.2~188.4   => 금속 43.5mm, 2단
```

**나사를 뺀 게 핵심이었다.** 코너 볼트가 `±0.0600`에 고정이라 사각 개구부를 키우면 볼트 패드를
먹는다. 나사를 빼니 개구부 모서리를 45°로 크게 깎을 이유가 사라져서, 모따기가 2.8mm(플레이트
자체 베벨이 안쪽으로 줄어든 값)인 **사실상 각진 사각형**이 됐다.

## 3. 막힌 것

**Unity MCP 브리지가 플레이 모드에서 응답을 멈춘다.**
에디터는 정상 실행 중이고 relay 재연결 로그도 뜨는데 툴 호출이 전부 타임아웃.
`runInBackground: 1` 도 켜져 있음. → 플레이 모드 검증은 사람이 직접 봐야 한다.

**Blender MCP 서버 파이썬 환경이 깨져 있다.**
```
ModuleNotFoundError: No module named 'blmcp'
```
editable 매핑(`~/Documents/GitHub/blender_mcp/mcp/blmcp`)도 맞고 `__init__.py` 도 있는데 import 실패.
**우회 방법(이번 세션에서 쓴 것)**: 애드온이 localhost:9876 에 직접 열려 있으므로 소켓으로 붙는다.
클라이언트: `{"type":"execute","code":"...","strict_json":false}` + `\0` 종단, 응답도 `\0` 종단 JSON.
헬퍼 스크립트는 세션 tmp 에 있었고, 필요하면 `addon/blender_mcp_addon/mcp_to_blender_server.py`
280~460행 보고 20줄로 다시 만들면 된다.

**헤드리스 블렌더는 이 환경에서 시작 자체가 죽는다.**
`MTLBackend::metal_is_supported` 에서 세그폴트. `--background --factory-startup --python-expr "print(1)"`
조차 죽음. GUI 세션에서만 실행 가능.

### 이것이 바꾸는 것

**리깅이 없다.** T-pose GLB 라 이번 세션에 만든 `PassengerEntryAnimator`(걸어 들어오기)를 붙이려면
리깅이 먼저다. 그러나 **가만히 서 있는 승객 4명**은 지금 바로 세울 수 있고, 그것만으로:

- 리뷰어 3명이 공통 지적한 "승객이 화면에 0픽셀" 해소
- 정민아가 말한 "스팀 캡슐 제작 가능 시점 = 승객이 씬에 실물로 서는 시점" 도달
- 한도경이 말한 "등 뒤에 시선이 존재한다는 사실 하나가 결과판을 읽는 매 순간에 비용을 부과한다" 성립

설 자리(`PassengerStationSet`, 슬롯 4개, 최소 간격 1.05m)는 이번 세션에 이미 만들어 뒀다.
GLB 24개를 받아서 `unity_scale` 적용해 슬롯에 세우는 것이 **다음 세션 1순위 후보**다.
