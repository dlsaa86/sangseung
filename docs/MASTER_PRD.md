# 1. 작업 원칙

각 마일스톤은 아래 루프를 수행한다.

`구현 → 컴파일·자동 테스트 → 실제 플레이 → 고정 시점 캡처 → 시각·가독성 평가 → 성능 측정 → 수정 → 재검증`

- 명백한 구현 세부사항은 합리적으로 결정하고 진행한다.
- 밸런스, 캐릭터 최종 디자인, 최종 모션, 최종 색·재질, 공포 표현 강도는 임의로 잠그지 않는다.
- 승인 대기 요소는 플레이스홀더와 2~3개의 교체 가능한 프리셋으로 구현한다.
- 가변 요소는 데이터 또는 프로파일로 분리한다.
- 불명확한 부분 때문에 작업을 중단하지 않는다. 안전한 기본값을 사용하고 `ASSUMPTION_LOG.md`에 기록한다.
- 새 핵심 시스템을 임의로 추가하지 않는다. 현재 코어 루프의 이해도, 감각적 긴장, 반복성을 먼저 검증한다.
- 가능하면 구현, QA, 비주얼 평가, 성능 감사를 역할 분리한다.
- 완료는 코드 작성량이 아니라 Definition of Done과 증거 산출물로 판단한다.

# 2. 제품 정의

## 2.1 한 줄 정의

1인칭으로 낡은 산업용 엘리베이터 안을 직접 돌아다니며 승객과 부품으로 영혼 수확 장치를 개조하고, 층마다 위험한 저항 계약을 선택한 뒤 자동 3×3 룰렛의 정화·패턴·캐스케이드를 거대한 전력 연쇄로 바꾸며 상승하는 오컬트 호러 로그라이크.

## 2.2 플레이어 판타지

플레이어는 빠른 반응으로 구슬을 멈추는 조작자가 아니다. 위험한 저항을 일부러 더 불러들이고 확률·패턴·재발동 규칙을 설계한 뒤, 큰 레버를 당겨 자신이 만든 엔진이 폭발하는 것을 지켜보는 운영자다.

## 2.3 감정 곡선

`낡고 불완전한 기계 → 불안한 첫 스핀 → 작은 정화 → 패턴 발견 → 자동 연쇄 → 요구 전력 돌파 → 멈출 수 있는데도 과수확 선택 → 엘리베이터 전체가 붕괴 직전으로 변함 → 성공 또는 후회 → 상승과 반전 단서`

## 2.4 노스스타

평범한 한 번의 레버 입력이 플레이어가 설계한 계약·승객·부품의 연쇄 발동을 통해 수초간 멈추지 않는 기계적·시청각적 폭주로 변해야 한다.

동시에 플레이어와 관전자는 다음을 따라갈 수 있어야 한다.

- 무엇이 발동했는가
- 왜 이득인가
- 지금 얼마나 위험한가
- 다음 선택에서 무엇을 바꿀 수 있는가

# 6. 룰렛 판정 요구사항

- 정상 영혼은 위치와 무관하게 기본 전력을 제공한다.
- 같은 종류 저항체가 3개 이상이고 **서로 인접**하면 정화한다 (직선 3연속 또는 연결 덩어리 4개 이상).
  위치와 무관한 개수 정화는 `D-20260801-03`으로 폐기됐다 — 사용자 요청이었고 근거는 그 항목에 있다.
- 기본 정화가 성립한 뒤 가장 높은 패턴 보너스를 판정한다.
- 초기 패턴은 직선 3개와 직교 연결 4개 이상만 사용한다.
- 4개 이상 연결 시 제거된 칸을 다시 채우고 재판정한다.
- 제거 → 빈칸 → 신규 심볼 유입 → 재판정 단계를 시각적으로 생략하지 않는다.
- 캐스케이드 하드 캡은 20회다.
- 캡 도달 시 오류로 멈추지 말고 명확한 로그를 남긴 뒤 정상 종료한다.

# 7. 과수확 — 2단 기계식 통합 레버

요구 전력을 이미 달성한 플레이어가 안전하게 끝낼 수 있음에도 더 큰 보상을 위해 위험을 자발적으로 선택하는 순간을 대표 장면으로 만든다.

> **2026-08-02 결정으로 「별도 레버」가 「하나의 2단 레버」로 바뀌었다.**
> 근거와 규격은 Notion `T-05` · `99. 결정 로그`. 아래는 그 동결 스냅샷이다.

- **물리 레버는 하나다.** 일반 스핀과 과수확이 같은 레버의 서로 다른 걸림점이다.
  두 기능은 **국면이 배타적**이라(스핀 중 / 결정 중) 같은 순간에 둘 다 유효한 경우가 없다.
- **첫 번째 걸림점**은 일반 스핀 전용이다.
- 요구 전력 100% 달성 시 **붉은 두 번째 이동 구간이 노출**된다.
- 과수확은 두 번째 걸림점을 넘는 **0.7~1.0초 유지 입력**으로 실행한다.
  한 번 당기는 것으로는 실행되지 않는다 — 그 유지 시간이 「자발적 선택」의 몸짓이다.
- **전력 확정은 별도 브레이크(또는 확정 버튼)** 로 실행한다. 안전 종료는 레버가 아니다.
- 목표 달성 후 첫 번째 걸림점만 당긴 경우 **스핀을 실행하지 않고** 선택 정보를 다시 표시한다.
- 선택 전 현재 확보 전력, 추가 가능 보상, 현재 위험, 실패 가능성, **예상 정산 가치**를 읽을 수 있어야 한다.
- 레버의 일반 구간과 과수확 구간이 **모션·음향·조명으로 명확히 구분**된다.
- 과수확은 단순한 점수 버튼이 아니라 조명, 음향, 진동, 승객 반응, 기계 상태를 변화시키는 공간적 사건이어야 한다.

## 7.1 남은 스핀 운행 효율 정산

**안전 확정이 실제 선택이 되려면 남은 스핀에 값이 있어야 한다.** 직전까지 안 쓴
스핀의 가치는 0 이었고, 그래서 과수확이 유일하게 합리적인 선택이었다.

- 안전 확정 시 남은 스핀을 **정산 가치로 변환**한다.
- 임시 기본값: 남은 스핀 1회당 요구 전력의 **5%**, 층당 상한 **요구 전력의 20%**.
- 초기 변환처는 **돈** 또는 장치 수리.
- **정산은 캐스케이드·임계점·승객·부품 효과를 발동하지 않는다.** 정산은 스핀이 아니다.
- **과수확을 선택하면 그 층의 정산 권리가 소멸한다.** 이 한 줄이 두 선택을 겨루게 만든다.
- 안전 정산 후 추가 스핀으로 되돌아갈 수 없다.
- 수치는 `RemainingSpinSettlementProfile` 로 데이터화한다 (임시값 — 교체 대상).

# 8. 계약, 승객, 부품과 무게

- 계약은 특정 저항체의 등장 가능성, 정화 보상, 잔류 대가를 함께 높인다.
- 계약은 항상 보상과 위험을 동시에 바꾼다.
- 승객과 부품은 룰렛 판정 또는 운영 규칙을 실제로 바꿔야 한다.
- 단순한 수치 증가만으로 4종을 채우지 않는다.
- 승객과 부품은 총 무게를 증가시키며, 무게는 요구 전력과 사고 위험에 영향을 준다.
- 서로 다른 최소 두 빌드가 실제 판단과 플레이 흐름을 바꿔야 한다.
- 최종 캐릭터 외형, 대사, 모션은 승인 전까지 교체 가능한 플레이스홀더로 유지한다.

# 9. 위험 상태와 공간 반응

게임 상태는 UI 숫자만이 아니라 엘리베이터 공간 전체로 표현한다.

초기 위험 프리셋은 최소 다음 단계를 포함한다.

- Stable: 정상 운용, 판독성이 가장 높은 기준 상태
- Strain: 과적 또는 잔류 저항 증가, 불안정한 징후
- Critical: 사고 직전, 강한 조명·음향·진동·승객 반응
- Collapse 또는 사고 상태: 제어 상실과 결과 기록

각 상태는 조명, 사운드, 기계 진동, 파티클, 계기판, 승객 행동에서 동기화되어야 한다. 특정 감각 채널 하나에만 의존하지 않는다.

# 10. 사고 기록기와 텔레메트리

런 또는 층 종료 시 플레이어가 결과와 실패 원인을 이해할 수 있는 기록을 제공한다.

필수 기록:

- 런 시드와 층 번호
- 선택 계약
- 초기 보드와 각 캐스케이드 단계
- 발동한 정화, 패턴, 승객, 부품
- 획득 전력과 요구 전력
- 잔류 저항과 위험 상태 변화
- 과수확 선택 여부
- 무게와 과적 상태
- 성공, 부분 성공, 사고 또는 런 종료 원인

# 11. 시각 평가 시스템

비주얼은 마지막 폴리시 단계가 아니다. 각 구현 마일스톤을 동일한 조건으로 캡처하고 평가한다.

필수 캡처:

- 엘리베이터 입구에서 본 전체 내부
- 룰렛 정면
- 계약 선택 상태
- Stable 상태
- Critical 상태
- 과수확 레버 접근 순간
- 5연쇄 이상
- 사고 직후와 사고 기록기
- 승객과 화물 최대 적재 상태

각 캡처는 동일한 해상도, FOV, 카메라 위치, 시간대, 품질 프리셋을 사용한다.

평가 항목:

- 한눈에 목적이 읽히는가?
- 상호작용물이 배경과 구분되는가?
- 정상 영혼, 흡수체, 증식체를 1초 안에 구분하는가?
- 정화와 캐스케이드 원인을 따라갈 수 있는가?
- Stable, Critical, 사고 상태가 명확히 구분되는가?
- 과수확 레버가 대표 선택으로 보이는가?
- 직전 승인 빌드보다 판독성과 분위기가 나빠지지 않았는가?

# 12. 플레이테스트 지표

- 첫 스핀 전 규칙 이해 시간
- 정상 영혼과 저항체 구분 성공률
- 같은 저항체 3개의 의미 설명 가능 여부
- 직선과 연결이 왜 더 좋은지 설명 가능 여부
- 계약이 보상과 위험을 함께 높인다는 점의 이해 여부
- 요구 전력 달성 후 고민 시간
- 과수확 선택률
- 플레이어가 실패 원인을 설명할 수 있는지
- 관전자가 무음 영상에서 상태를 설명할 수 있는지
- 멀미, 섬광, 사이렌 피로도

# 13. Definition of Done

## 13.1 기능 완료

- 개발자 조작 없이 1층부터 10층까지 플레이 가능
- 계약, 스핀, 정화, 직선, 연결, 캐스케이드, 잔류, 승객·부품, 과수확, 성공·실패가 연결됨
- 감각적 위험 상태가 실제 게임 상태와 동기화됨
- 사고 기록기가 런 데이터를 정확히 출력함

## 13.2 기술 완료

- 핵심 EditMode 테스트 통과
- 필요한 PlayMode 테스트 통과
- 치명적 콘솔 오류 없음
- 동일 시드 재현 가능
- 캐스케이드 무한 루프 없음
- 10층 연속 플레이 중 진행 불가 상태 없음
- 결과 로그 저장 가능
- 지정 하드웨어 기준 성능 조건 충족

## 13.3 경험 완료

- 플레이어가 핵심 규칙을 설명할 수 있음
- 과수확이 실제 고민으로 작동함
- 서로 다른 두 빌드가 판단을 바꿈
- 실패 원인을 사고 기록기로 설명할 수 있음
- 관전자가 무음 영상에서도 상태 변화를 읽을 수 있음

## 13.4 비주얼 완료

- 비주얼 루브릭 통과
- Stable, Critical, Collapse가 명확히 구분됨
- 결과판 심볼 3종이 1초 내 구분됨
- 캐스케이드 원인이 읽힘
- 사용자 승인 대기 항목은 교체 가능한 상태로 유지됨

## 13.5 증거 산출물

완료 보고에는 다음이 포함되어야 한다.

- 실행 가능한 Windows 빌드
- 테스트 결과 요약
- 성능 캡처와 GC Alloc 결과
- 고정 시점 스크린샷 세트
- 핵심 흐름 영상
- 변경 파일 목록
- 사용한 시드와 재현 절차
- 남은 위험과 승인 필요 항목

# 14. 구현 단계

## Phase 1 — 결정론적 코어

룰렛 데이터, 계약, 정화, 패턴, 캐스케이드, 테스트를 구현한다.

통과 조건: Unity 씬 없이 핵심 EditMode 테스트가 통과하고 동일 시드가 재현된다.

## Phase 2 — 플레이 가능한 그레이박스

1인칭 이동, 상호작용, 레버, 계약 패널, 전력 계기판, 10층 흐름을 구현한다.

통과 조건: 플레이어가 디버그 조작 없이 10층을 진행한다.

## Phase 3 — 빌드와 과수확

승객·부품, 무게, 요구 전력, 과수확 레버를 구현한다.

통과 조건: 서로 다른 두 빌드가 실제 판정 규칙과 의사결정을 바꾼다.

## Phase 4 — 공간 반응

위험 상태, 조명, 사운드, 진동, 승객 반응, 사고 기록기를 구현한다.

통과 조건: 무음 영상과 오디오만 듣는 테스트 모두에서 위험 단계 변화를 구분할 수 있다.

## Phase 5 — 비주얼·성능 반복

스타일 셰이더, 조명, 파티클, 재질, 캡처, 프로파일링을 반복한다.

통과 조건: 비주얼 루브릭과 기술 완료 조건을 모두 만족한다.

## Phase 6 — 사용자 승인 게이트

캐릭터 디자인, 모션, 색·재질, 밸런스, 공포 강도 프리셋을 비교 가능한 형태로 제출한다.

통과 조건: 사용자가 선택하거나 수정 지시를 내릴 수 있고, 선택 변경이 대규모 코드 수정 없이 적용된다.

# 15. 에이전트 시작 지시

1. 저장소와 Unity 프로젝트 구조를 읽고 현재 구현 상태를 이 문서에 매핑한다.
2. 이미 정상 동작하는 시스템을 이유 없이 재작성하지 않는다.
3. 누락, 충돌, 기술 부채를 `docs/runtime/GapAnalysis.md`에 기록한다.
4. 사소한 모호성은 `docs/ASSUMPTION_LOG.md`에 기본값과 교체 위치를 기록한다.
5. `CURRENT_PHASE.md`의 범위부터 순서대로 구현한다.
6. 기능 구현 뒤 반드시 테스트, 플레이, 캡처, 시각 평가, 성능 측정을 수행한다.
7. 실패한 테스트나 기준 미달을 숨기지 않는다.
8. 승인 대기 요소는 비교 가능한 프리셋으로 제출한다.
9. 사용자 승인이 없어도 코어 시스템과 교체 가능한 플레이스홀더 구현은 계속 진행한다.
10. 완료 보고는 Definition of Done과 증거 산출물을 항목별로 대조해 작성한다.
