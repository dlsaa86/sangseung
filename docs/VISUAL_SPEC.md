# Visual Specification — 상승

> 상태: 프로토타입 비주얼 기준  
> 상세 평가 루브릭: `.claude/visual-criteria.md`

# 1. 핵심 방향

- 낡은 1960년대 산업용 화물 엘리베이터
- PS1 및 초기 PS2 생존 호러의 저해상도 감각
- 단순하고 각진 로우 폴리 실루엣
- 픽셀화된 손그림 텍스처
- 화려한 스팀펑크, 카지노 슬롯머신, 장식적인 황동 기계는 피한다.
- 공간은 좁고 높고 기능적이어야 한다.
- 기계는 오래되고 위험하지만 각 기능의 대응 관계는 명확해야 한다.

# 2. 대표 공간

엘리베이터 내부는 게임의 주 무대이며 다음 요소를 포함한다.

- 녹슨 금속 바닥
- 리벳과 패널이 드러난 벽
- 낡은 접이식 가위문 또는 무거운 산업용 문
- 어두운 외부 복도
- 희미한 천장 조명
- 승객과 화물을 위한 빈 바닥 공간
- 벽면에 결합된 모듈식 영혼 수확 장치

엘리베이터는 장식 세트가 아니라 게임 상태를 표현하는 거대한 피드백 장치다.

# 3. 룰렛 장치

- 세 개의 수직 통관이 나란히 배치된다.
- 각 통관은 결과판의 한 열과 대응한다.
- 자동 3×3 결과 구조가 정면에서 즉시 읽혀야 한다.
- 통관, 결과판, 전력 계기판, 일반 실행 레버, 과수확 레버의 역할을 혼동하지 않아야 한다.
- 기계는 향후 모듈 확장이 가능한 프레임 구조를 가진다.
- 케이블과 파이프는 기능적 연결을 설명할 때만 사용한다.
- 작은 디테일을 무분별하게 추가해 실루엣을 흐리지 않는다.

# 4. 심볼 식별

정상 영혼, 흡수체, 증식체는 색상 하나에만 의존하지 않고 다음 중 최소 세 가지가 달라야 한다.

- 외곽 실루엣
- 내부 오브제 또는 패턴
- 발광 방식
- 움직임 또는 맥동
- 텍스처 밀도
- 공개 사운드

목표: 정면 게임 화면에서 1초 안에 세 종류를 구분한다.

# 5. 상호작용 계층

상호작용물은 배경과 분리되어야 하지만 현대적 HUD처럼 떠 보이면 안 된다.

우선순위:

1. 현재 사용 가능한 핵심 레버
2. 현재 결과와 큰 배수
3. 요구 전력과 현재 전력
4. 계약과 잔류 위험
5. 승객·부품 발동
6. 보조 수치와 디버그 정보

한 화면에 모든 숫자를 동시에 강조하지 않는다.

# 6. 위험 상태

## Stable

- 기본 판독성을 위한 기준 상태
- 조명과 사운드는 낮은 긴장감을 유지
- 심볼과 상호작용물 구분이 가장 선명함

## Strain

- 잔류 저항 또는 과적 증가가 공간에 나타남
- 작은 깜빡임, 기계 떨림, 승객 불안 반응
- 판독성을 해치지 않는 수준

## Critical

- 조명, 음향, 진동, 증기 또는 입자가 함께 강화됨
- 공간이 붕괴 직전처럼 느껴지지만 핵심 결과는 읽혀야 함
- 무작위 전체 화면 흔들림과 과도한 섬광을 피함

## Collapse / Accident

- 제어 상실과 결과를 명확히 전달
- 실패 원인이 사고 기록기로 이어져야 함
- 단순한 암전이나 즉사 연출로 정보를 숨기지 않음

# 7. 과수확 레버

과수확 레버는 대표 장면의 중심이다.

- 일반 실행 레버보다 크고 무겁다.
- 보호 덮개, 잠금 장치 또는 별도 위치로 구분한다.
- 요구 전력 달성 전에는 물리적으로 잠겨 보인다.
- 해제 순간 조명, 소리, 기계 반응이 집중된다.
- 선택 전 위험을 읽을 수 있어야 한다.
- 붉은색 하나만으로 위험을 표현하지 않는다.

# 8. 카메라와 화면

- 기준 해상도: 1920×1080
- 고정 비교 캡처에서는 동일한 FOV와 카메라 위치를 사용한다.
- 1인칭 시점에서 상호작용 거리를 일관되게 유지한다.
- 과도한 카메라 흔들림, 강한 렌즈 왜곡, 지속적인 색수차는 피한다.
- 로우파이 스타일을 명분으로 결과 판독성을 희생하지 않는다.

# 9. 캡처 세트

- 엘리베이터 입구에서 본 전체 내부
- 룰렛 정면
- 계약 선택 상태
- Stable 상태
- Critical 상태
- 과수확 레버 접근 순간
- 5연쇄 이상
- 사고 직후
- 사고 기록기
- 최대 적재 상태

# 10. 평가 규칙

각 항목을 1~5점으로 평가하고 근거를 기록한다.

- 목적과 흐름이 한눈에 읽히는가?
- 상호작용물이 배경과 구분되는가?
- 심볼 3종을 1초 안에 구분하는가?
- 정화와 캐스케이드 원인을 따라갈 수 있는가?
- 현재 전력과 위험을 이해할 수 있는가?
- Stable과 Critical이 명확히 구분되는가?
- 과수확 레버가 대표 선택으로 보이는가?
- 스타일이 산업용 로우폴리 호러 방향을 유지하는가?
- 직전 승인 빌드보다 나빠지지 않았는가?

구현자는 자신의 변경을 최종 승인하지 않는다. 가능하면 블라인드 비교를 사용한다.

# 11. 승인 대기 항목

다음 항목은 하나의 최종안으로 잠그지 않는다.

- 캐릭터 외형
- 승객 실루엣
- 최종 모션
- 최종 색 조합
- 재질 마감
- 공포 표현 강도
- 섬광과 카메라 흔들림 수준

2~3개의 교체 가능한 프리셋과 동일 조건 캡처를 준비한다.

# 12. 레퍼런스에서 유도한 수치 목표 (2026-08-04)

> 이 절은 §10 평가 규칙을 **대체하지 않는다.** §10 은 사람이 보는 항목이고,
> 여기는 그 판정 전에 자동으로 걸러낼 수 있는 **수치 하한선**이다.

## 왜 만들었나

2026-08-04 야간 세션에서 목표치를 네 번 세웠는데 **네 번 다 내가 지어낸 값**이었다.
그러다 사용자가 준 레퍼런스 이미지를 직접 측정하고 나서야, 내가 맞추려던 것과
레퍼런스가 서로 다른 곳에 있다는 것이 드러났다.

측정: `tools/measure_reference_band.py` (sRGB 가중 휘도. 이 저장소 보고 규약과 동일)

```
docs/references/elevator/mood_20260804_user_cabin.png
  mean .0647  p50 .0512  p99 .3097  <0.02 25.41%  >0.50 0.26%  g/r 0.829  b/r 0.524
```

## 목표 대역

| 지표 | 레퍼런스 | 허용 대역 | 뜻 |
|---|---|---|---|
| mean | .0647 | **.055 ~ .075** | 전체 밝기 |
| p50 (중앙값) | .0512 | **.040 ~ .062** | 화면 절반이 이보다 어둡다 |
| p99 | .3097 | **.25 ~ .36** | 하이라이트가 타지 않는다 |
| `<0.02` | 25.4% | **≤ 32%** | 완전 검정이 화면의 1/3 을 넘지 않는다 |
| `>0.50` | 0.26% | **≤ 0.5%** | 밝은 이상치가 거의 없다 |
| **g/r** | **0.829** | **0.78 ~ 0.90** | **빨강 우세 — 따뜻하다** |
| **b/r** | **0.524** | **0.45 ~ 0.62** | 파랑이 가장 약하다 |

## 가장 중요한 항목은 색조다

레퍼런스는 **따뜻하다** (r > g > b). `VISUAL_BIBLE` §3 의 「탁한 갈색 · 더러운 올리브」와
일치하고, **차가운 회녹색은 §2.1 이 「그림자 색」으로 한정**한 것이지 방 전체의 색이 아니다.

2026-08-04 실측 대조 — **작업이 진행될수록 색조가 레퍼런스에서 멀어졌다.**

| | g/r | b/r |
|---|---|---|
| 레퍼런스 | 0.829 | 0.524 |
| 기준선 (작업 전) | 0.901 | 0.816 |
| v4 (작업 후) | **1.125 ~ 1.462** | 0.728 ~ 0.827 |

밝기·대역비·판독성은 개선됐지만 **색조만은 시작보다 나빠졌다.**
값을 재는 축이 하나 빠져 있으면 그 축은 조용히 나빠진다 — 이 표가 있는 이유다.

## ⚠ 캡처는 post-processing ON 으로 찍는다

2026-08-04 발견 — 기준선·v1·v2 캡처가 전부 post OFF 였고, 같은 씬에서
post ON 과 **2.1배** 차이가 났다. 즉 평가 대상이 플레이어가 보는 화면이 아니었다.

**판정용 캡처는 반드시 post ON 이다.** post OFF 는 연속성 비교용으로만 남긴다.
`Captures/baseline.txt` 와 과거 판정이 어느 기준이었는지는 **미확인 — 다음 세션 확인 항목.**
