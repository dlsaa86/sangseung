## 이 세션에서 얻은, 다음이 반복하지 않아야 할 것

### 환경

- **블렌더 MCP 애드온은 NUL 프레이밍이다.** JSON 뒤에 `\0` 을 안 붙이면 응답 0바이트.
  커뮤니티 `ahujasid/blender-mcp` 와 다른 프로토콜이다(공식 `lab_blender_org/mcp`).
- **블렌더가 `~/Documents` 를 열면 메인 스레드가 통째로 멈춘다.** macOS TCC 대화상자가
  백그라운드라 안 보인 채 `open()` 이 클릭을 기다린다. Unity 모달 잠금과 같은 구조.
  진단은 `sample <pid>` 로 스택을 뜬다 — 추측하지 말 것.
  **예방: 블렌더가 `~/Documents` 를 읽지도 쓰지도 않게 한다.**
- **백그라운드 블렌더는 요청당 지연이 수십 초다.** 20초엔 무응답, 90초엔 응답.
  죽은 게 아니라 느리다. **잘게 쪼개지 말고 한 번에 크게 보낸다.**
- **`Renderer.bounds` 는 같은 프레임에 낡는다.** 스케일을 바꾸고 바로 재면 안 변한 것처럼
  보인다. 정점을 `TransformPoint` 로 직접 변환해야 정확하다.
- **꺼진 콜라이더의 `bounds` 는 크기 0 이다.**
- **캡처 RenderTexture 에 `antiAliasing` 을 안 걸면** MSAA 를 우회해 언제나 계단이 보인다.
  고쳐 놓고 「안 고쳐졌다」로 오진할 수 있다.
- **편집 모드에서는 `OnEnable` 이 안 불린다.** 이벤트 구독에 기대는 테스트는 편집 모드에서
  거짓 음성이 난다. 상태 기계를 직접 부를 것.
- **`HashSet<T>` + LINQ 는 MCP `Unity_RunCommand` 에서 `ISet<>` 참조 오류가 난다.**
  `List<T>` 를 쓴다. `GetInstanceID()` 도 폐기됐다 — `GetEntityId()`.

### 구조

- **`CabinAD47` 은 FBX 모델 프리팹 인스턴스다.** 기존 자식을 **재배치할 수 없다**
  (새 자식 추가는 된다). 게이지 위젯을 그래서 새로 만들었다.
- **같은 이름의 물체가 서로 다른 루트에 있다.**
  `InteractableLever` 는 `GrayboxWorld/Car/Console/ExecutionLever`,
  `LeverStateMachine` 은 `ReferenceRoom/ExecutionLeverBase/ExecutionLeverHandle`.
  **계층 탐색(`GetComponentInParent`)으로는 서로를 못 찾는다.** UnityEvent 로만 이어져 있다.
- **`GrayboxWorld` 와 `CabinAD47` 이 같은 것을 두 벌씩 들고 있다.** 코드가 어느 쪽을
  가리키는지 반드시 확인할 것 — 전력 게이지가 정확히 그 함정이었다(숨겨진 옛 바를 구동).
- **`AD53_BAKEALL` 의 `ORDER` 가 5개 낡았다** (삭제된 벽 판재 4장 + `SM_Door_Track`).
  알베도 재굽기도 같은 자리에서 실패한다.

### 판단

- **수치가 통과해도 그림을 본다.** 이 세션에서 이 유형이 네 번 나왔다 —
  AO 평균 0.08(배경 탓), AO 배선 후 휘도 변화 0(존재하지 않는 항을 겨냥),
  PANEL 은 멀쩡한데 DOOR 에 크림색 반원, 게이지가 숨겨진 물체를 움직임.
- **계약이 상속 관계일 때 아래쪽 분기에 배제 조건을 넣는다.**
  `ITapAndHoldInteractable : IHoldInteractable` 에서 그것을 빠뜨려 **일반 스핀도 0.85초
  꾹 눌러야** 하게 만들었다. 컴파일도 테스트도 못 잡는다.
- **앵커(위치의 출처)와 교체 대상(끌 것)을 한 변수로 겸하지 않는다.**
  앵커를 바꾸는 순간 조용히 다른 것을 끈다.
