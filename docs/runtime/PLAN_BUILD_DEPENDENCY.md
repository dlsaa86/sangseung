## C-1. 현재 판정 — 이미 배치를 본다

### 기존 패턴 4가지 (코드에 존재)

**파일:** SpinEngine.cs:479~536 / PatternKind.cs

| 패턴 | 판정 기준 | 배수 | 구현 |
|---|---|---|---|
| **FullBoard** | 9칸 전부 같은 저항 | 10.0× | `board.CountOf(kind) == 9` |
| **Cluster** | 4칸 이상 직교 연결 (또는 대각) | 3.0× | `FindConnectedComponent(..., 4)` |
| **Line** | 가로/세로/대각 직선 3칸 | 2.0× | `TryFindLine(board, kind)` |
| **Scattered** | 2~3칸 인접 (형태 없음) | 1.0× | `FindConnectedComponent(..., MinCount)` |

**현황:** 종류별로 **독립적**으로 판정. 상호작용 없음.

## C-2. 제안: 두 종류의 상대 배치 패턴 5가지

**3×3, 심볼 3종 조건에서 판독 가능하고 구현 가능한 패턴:**

### 1. Cross (십자) — 흡수체 중심 + 증식체 바퀴

```
배치:  E A E     판정: 흡수 1개 중심(1칸) + 증식 4개 직교 인접
      A P A          배수: 5.0× (Line 2.0 + Cluster 3.0 합성)
      E A E     발생률: 추정 3% (중심과 4방향 2칸 필요)
                판독성: ★★★ (한눈에 보임)
```

### 2. Stripe (줄무늬) — 교대 배치

```
배치:  A E A     판정: 2행 이상, 양쪽이 교대로 다른 저항
      E A E          배수: 4.5× (패턴 보너스 1.5 추가)
      A E A     발생률: 추정 2% (규칙적 배치는 드뭄)
                판독성: ★★★
```

### 3. Frame (테두리) — 외곽이 한 종류, 중심이 다른 종류

```
배치:  A A A     판정: 8칸 경계 + 1칸 중심이 다른 저항
      A P A          배수: 3.5× (Cluster와 비슷, 중심 안정성 보상)
      A A A     발생률: 추정 5% (테두리는 자주 같이 나옴)
                판독성: ★★★
```

### 4. Duo (쌍) — 같은 종류 2개 + 다른 종류 인접

```
배치:  A A X     판정: 한 종류 2칸 이상 + 다른 종류와 인접
      X . X          배수: 2.5× (기본 이상의 "조화" 보상)
      . . . 발생률: 추정 15% (매우 자주, 기본값)
                판독성: ★★ (명시적 구분 필요)
```

### 5. Cycle (순환) — 3종류 모두 포함 (심볼 4종 추가 후)

```
조건: 심볼 4종 필요
배치:  A P A     판정: 세 종류 모두 최소 1칸씩 포함 (3×3 안에서)
      P X P          배수: 6.0×
      A P A     발생률: 추정 8% (3종류 이상 함께 나올 확률)
                판독성: ★★★ (심볼 시각 설계로 달성 가능)
```

**블렌더 의존성:** 심볼 3종을 실루엣(색상 무관)으로 갈려면 위 5가지 모두 판독 가능. 
4번째 종류 추가 시 Cycle 패턴이 해금된다.

## C-3. 「그래야만 올라간다」를 만드는 수치 구조

### 현재 상태 분석

**1층 요구: 330 (기본값)**
- 무빌드 기본산: 스핀 3회 510 (237%) — **패턴 없어도 초과**
- 문제: 패턴이 보너스가 아니라 **필수 조건**이 아님

### 목표 수치 구조

**기본산 (패턴 없음) = 요구의 70~80%**
- 목표: 스핀 3회 210~264 → 요구 330 미만
- 조정 방법: NormalSoulValue 14.0 → 11.5 (~20% 감소)

**상대 배치 패턴 = 요구를 충족시키는 추가분**
- Cross (5.0×): 210 × 5.0 = 1050 (330 초과, 넉넉함)
- Stripe (4.5×): 210 × 4.5 = 945
- Frame (3.5×): 210 × 3.5 = 735
- Duo (2.5×): 210 × 2.5 = 525 (기본 + 195 = 초과)

**결론:**
- 무빌드 + 운: 기본산 210 → 요구 330 미만 (불충분) ← **진행 가능하지만 어려움**
- 무빌드 + 패턴 1회: 210 + 패턴 2.5~5.0× = 525~1050 (충분)
- 빌드 + 패턴: 기본산 20% 증가 + 패턴 확률 2배 → 대부분 달성

**수치 설정:**
```
1층: NormalSoulValue 11.5, RequiredPower 330
2층~5층: NormalSoulValue 11.5, 요구 조정 (기본산 대비 80%)
6층~10층: NormalSoulValue 11.0 (추가 상향), 패턴 중복 해금 (AllowMultiplePatternsPerKind)
```

## C-4. 빌드가 패턴 확률을 바꾸는 방법

### 현재 BuildEffect가 가능한 것

**파일:** BuildItem.cs:52~108 (BuildEffectKind enum)

| 효과 | 규칙 수정 | 패턴과의 관계 |
|---|---|---|
| `Appearance` | 저항 가중치 × N | 특정 종류를 더 자주 → 패턴 빈도 ↑ |
| `PurifyThreshold` | 정화 최소 개수 3→2 | 정화율 ↑, 패턴 성립 용이 |
| `DiagonalConnects` | 대각 연결 인정 | Cluster 확률 ↑ |
| `PatternBonus` | 패턴 배수 +N | Cross/Stripe 배수 상향 |
| `RefillSoulBias` | 재충전 시 영혼 확률 ↑ | 정화 가능성 ↑ |
| `ClusterMultiplier` | 4칸 연결 배수 +N | Cluster 보상 ↑ |

**부족한 것 (새로 추가 필요):**
- `TargetPairFrequency`: 두 종류가 인접할 확률 ↑ (Duo 패턴 필수)
- `CrossPatternMode`: Cross 중심을 특정 종류로 고정 (확률 × 2)
- `FrameBuilder`: 테두리/중심 역할 역전 (전략 다양화)

## C-5. 빌드 선택의 갈래

### 3가지 독립 경로 (지배적 선택 회피)

| 빌드 | 목표 패턴 | 주요 효과 | 특징 |
|---|---|---|---|
| **안정형** | Duo + Scattered | PurifyThreshold 2 + Appearance 흡수 1.2× | 기본 최소개수로 계속 정화, 안전 |
| **조화형** | Cross + Stripe | DiagonalConnects + PatternBonus 1.5 | 두 종류 균형, 높은 배수 |
| **폭발형** | Cycle + ClusterMultiplier | Appearance 증식 1.5× + 연결 배수 4.0 | 드물지만 큰 연쇄 |

**선택지 수:** 3가지 이상 (1가지만 최고 우위가 아니므로 지배적 선택 회피)

## C-6. 4번째 심볼 필요한가?

### 결론: **필요 없다** (패턴 시스템으로 충분)

**이유:**
1. 현재 3종 + 상대 배치 5패턴 = 조합 폭발
2. 각 층에서 3~5개 패턴 해금 → 경우의 수 충분
3. Cycle 패턴만 해도 3종 모두 필요 → 4종은 과하지 않을까?

### 만약 추가한다면: **동조형(Resonance) 심볼**

**규칙 역할:**
- "다른 종류와 인접하면 둘의 배수를 곱한다"
- 예: Resonance 1칸 + 흡수 3칸 인접 → 3×2.5 = 7.5배 (시너지)

**효과:**
- Cycle 패턴이 자연스럽게 가장 높은 배수 (8.0~10.0)
- 4종 추가의 정당성 생김 (독립 캐릭터, 지배 선택 아님)

**블렌더 작업:**
- 지금 3종 실루엣 디자인 중 → 4번째를 "울림"이나 "공명" 시각으로 표현 가능
- 같은 배치에서 만들 수 있음 (반투명, 빛 이펙트 등)
