## 왜 되돌리지 않는가 (사용자 결정)

- 내용 자체는 **손상되지 않았다.** 컴파일도 통과한다.
- 히스토리 재작성은 되돌리기 어렵고, 상대가 같은 브랜치를 쓰고 있으면 **충돌한다.**
- 섞인 파일만 커밋에서 빼는 것도 위험하다 — 상대가 그 파일을 계속 쓰고 있으면
  작업을 날린다.

그래서 **그대로 두고 이 문서로 기록만 남긴다.** 다음에 히스토리를 읽는 사람이
`e3986d6`·`baeeb61`·`6059b5d` 의 메시지와 내용이 어긋나는 것을 보고 혼란스러워하지
않도록 하는 것이 이 문서의 목적이다.

## 무엇을 잘못했나

1. **`git add -A` 를 썼다.** 병렬 작업 가능성이 있는 저장소에서 전체 스테이징은
   남의 작업을 쓸어 담는다. 내가 고친 파일을 **명시적으로** 지정했어야 한다.
2. **미커밋 파일을 보고 「내가 앞서 만든 것」이라고 단정했다.** 파일 시각을 먼저
   보거나 내용을 내 작업 기록과 대조했어야 한다. 커밋 메시지에 사실이 아닌 문장을
   남겼다.
3. `CLAUDE.md` 의 「에이전트 소유권 규칙」이 정확히 이 상황을 경고한다.
   읽어 두고도 병렬 가능성을 확인하지 않았다.
