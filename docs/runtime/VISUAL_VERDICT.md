# VISUAL VERDICT — 독립 시각 평가 판정

> **구현자가 이 파일을 쓰지 않는다.** 구현자와 분리된 평가자(`visual-critic` /
> `visual-director` 또는 `visual-verify` 스킬의 블라인드 평가자)만 판정을 기록한다.
> `tools/verify-topdown.ps1` C10 이 마지막 `VERDICT:` 줄 하나만 읽는다.
>
> **판정 파일이 캡처 매니페스트보다 오래되면 검증기가 거부한다.** 캡처를 다시 뽑았으면
> 평가도 다시 받아야 한다 — 옛 ACCEPT 를 새 캡처에 재사용할 수 없다.

## 형식

각 평가는 아래 블록 하나를 **파일 끝에 추가**한다. 이전 기록을 지우지 않는다.

```
## <YYYY-MM-DD> — <대상 캡처 세트>
- 평가자: <구현자와 분리된 주체>
- 대상: Captures/<set>/manifest.txt  (machineFingerprint: <값>)
- 방식: 블라인드 쌍대비교 / 루브릭 채점
VERDICT: ACCEPT | REJECT | PENDING
- 근거: <한 문단>
- 지적 → 백로그 전환: <UP-FIX-NN 목록>
```

`VERDICT:` 는 **줄 전체가 정확히** `VERDICT: ACCEPT` 형태여야 한다 (앞뒤 공백 허용).

### 다만 지표가 또 다른 쌍을 가리킨다

7차의 교훈은 「기준점으로부터의 거리는 인접 구분 가능성을 재지 못한다」였다.
**같은 형태의 오차가 이번에도 났다.** 구현자는 Strain↔Critical 을 고쳤다고 적었는데,
실측상 지금 **가장 약한 인접 쌍은 Critical↔Collapse** 다 — 좌벽 ΔL 5.6, 그리고
**직접광을 받는 보드 선반면에서는 06→09→10 이 99.3 / 98.7 / 97.3 으로 Δ<2 (0.8%)** 다.

즉 틴트는 **그늘진 면에만 도달하고 밝은 면에는 도달하지 않는다.** 7차의 한계 지적
(「실제 플레이 중 시선은 보드에 고정돼 있고 그 시야 안에서는 같은 색이다」)이
**절반만 닫혔다** — 보드의 어두운 부분은 따라오지만 밝은 프레임·선반은 그대로다.

## 4. 가장 넓은 결함 — 상태 패널 좌측을 유리 통관이 먹는다 (11장)

   **한 패널에 요구값이 둘이고 서로 다르며, 전력 933 / 요구 1508 은 62% 인데 0% 라고 적혀 있다.**
   `17` 은 그 패널을 오버레이 위에 겹쳐 같은 모순을 한 번 더 보여 준다.
   8차가 「`UP-FIX-11` 해결 · 자기모순 0건」으로 닫은 항목이 **다른 장에서 다시 열렸다**이고,
   `19` 의 「999% ↔ 1,415 %」와 합쳐 **자기모순 장이 1장에서 3장으로 늘었다.**
2. **패널의 깨진 가장자리가 좌 → 우로 옮겨 갔다** (§2). 다섯 라운드 연속이다.
   그리고 옮겨 간 자리에 있던 것이 하필 **대가의 수치**(−16.0 / −24.0 / −32.0)와
   **위험 문구**(추락 위험)와 **판돈**이다.
3. **`21` 이 후퇴했다.** 8차가 「9칸 + 4줄 중 3줄이 가림 없이 동시에 읽히는 **유일한 장**」으로
   기록한 프레임에서 지금은 「위험도 안정」이 「위힘」에서 잘리고, 「요구 350  0」에서 % 가
   사라지며, **게이지 눈금 5개 중 3개만 보인다.**
4. **`17` 의 텍스트 겹침이 심해졌다.** 8차는 「반투명 오버레이라 월드 패널 글자가 비친다」였는데,
   지금은 월드 패널이 **오버레이보다 앞에 더 크고 밝게** 그려져 「종료 원인 … 70% 미만」 위에
   「과수확 없이 확정」이 얹힌다.
5. **`15`·`19` 의 페이라인이 굵어지고 금색이 됐다** — 3라운드 연속 지적받은 그림이 강화됐다.
6. **매니페스트가 새로 도입한 계측이 22건의 거짓 레드를 낸다** (§2-①).
   측정을 시작한 것은 옳지만, 지금 상태로는 실제로 고친 성과를 파일이 부정한다.
