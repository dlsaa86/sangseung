## 1. 플레이어 행동

### 1.1 조작 (확정)

| 입력 | 동작 |
|---|---|
| `WASD` | 엘리베이터 내부·문 밖 제한 공간 이동 |
| 마우스 | 1인칭 시점 |
| 화면 중앙 조준점 + 좌클릭 | 상호작용 (승객·계약 장치·레버·계기판·아이템) |

**상호작용 규칙 (확정 — 기술 부록 08 §15.2)**

- 화면 중앙 레이캐스트
- **클릭 1회로 실행**
- **길게 누르기 금지** — ⚠ 예외 1건, §4.3 참조
- 작은 버튼 정밀 조준을 요구하지 않는다
- 대상 콜라이더는 시각 모델보다 약간 크게
- 상호작용 거리 **2.5m** (초기값, 원문 "권장값")

**금지 (확정)**: 작은 칸이나 빠르게 움직이는 심볼을 직접 클릭하게 하지 않는다. 룰렛 판정은 전부 자동이다.

### 1.2 판정 중 이동 (확정)

자동 연쇄 중에도 이동과 시점 회전을 허용한다.
단 **등을 돌려도** 사운드·전력 계기판·보조 UI로 핵심 결과를 알 수 있어야 한다.

## 2. 룰렛 판정

### 2.1 장치와 보드 (확정)

- 투명 수직 통관 **3개**, 각 통관이 한 스핀에서 **3개** 포획 → **3열 × 3행 = 9칸**
- 인덱스 규약: `row * 3 + column`으로 **통일**, 외부 API는 행·열 접근자 제공
- 플레이어 입력 장치는 **레버 1개 + 전력 확정 브레이크 1개**

### 2.2 심볼 (확정 / 초기값)

| 심볼 | ID | 역할 | 기본 전력 | 정화 보상 | 잔류 대가 |
|---|---|---|---|---|---|
| 정상 영혼 | `normal_soul` | 위치 무관 즉시 수확 | **10** (초기값) | — | — |
| 흡수체 | `absorber` | 저항체 | — | **18** (초기값) | 남은 1개당 현재 층 전력 **−5** (초기값) |
| 증식체 | `replicator` | 저항체 | — | **15** (초기값) | 남은 1개당 다음 스핀 가중치 **+5%** (초기값), 층 종료 시 초기화(확정) |

**심볼별 기본 출현 가중치는 전 문서 미명시.**

### 2.3 정화 조건 — 🔴 가장 중요한 규칙 (확정)

> 같은 종류 저항체가 **3개 이상이고 서로 인접**하면 정화한다.
> (직선 3연속 또는 연결 덩어리 4개 이상)

**위치 무관 개수 정화는 `D-20260801-03`으로 폐기됐다.** 사용자 요청이었다.

⚠ **Notion 참고 원본 4개(00 · 01 · 07 · 99)가 아직 "위치와 무관하게"라고 적고 있다.**
Notion을 참조할 때 이 함정에 빠지지 말 것. 최신은 MASTER PRD §6.1이다.

**인접의 정의 (확정)**
- 연결 판정은 **상하좌우 직교 인접**만 사용한다
- **대각선은 연결 덩어리에 포함하지 않는다.** 대각선 3칸은 *직선 패턴*으로만 별도 인정
- 판정과 제거 **둘 다** 인접을 따른다

### 2.4 패턴 (확정 / 초기값)

| 패턴 | 조건 | 배수 (초기값) | 재충전 |
|---|---|---|---|
| 개수 정화 | 인접 3개 이상 | ×1.0 | ✗ |
| 직선 3개 | 가로·세로·대각선 | ×1.5 | ✗ |
| 4개 직교 연결 | BFS 덩어리 ≥4 | ×2.0 | ✓ |
| 5개 연결 | ≥5 | ×2.5 | ✓ |
| 6개 이상 연결 | ≥6 | ×3.0 | ✓ |

**우선순위 (확정)**: `6개 이상 > 5개 > 4개 > 직선 > 개수 정화`.
한 저항체가 여러 패턴을 만들어도 **가장 높은 것 하나만** 적용한다.
(여러 패턴 중복 판정은 업그레이드 해금 — 프로토타입 범위 밖.)

### 2.5 캐스케이드 (확정 / 초기값)

**흐름**: 제거 → 빈칸 → 신규 심볼 유입 → 재판정. **이 단계를 시각적으로 생략하지 않는다.**

| 단계 | 배수 (초기값) |
|---|---|
| 1 | ×1.0 |
| 2 | ×1.25 |
| 3 | ×1.5 |
| 4 | ×2.0 |
| 5 이상 | 단계당 +0.5 |

**적용 범위 (확정)**: 캐스케이드 배수는 **해당 단계에서 발생한 정화 전력에만** 적용한다.

**종료 조건 4종 (확정)**: 제거할 패턴 없음 / 하드 캡 도달 / 유효 심볼 풀 없음 / 치명적 데이터 오류.

**하드 캡 = 20회 (확정)**. 캡 도달 시 **오류가 아니라 안전 종료**로 처리하고 텔레메트리에 기록한다.

> 하드 캡은 밸런스 다이얼이 아니라 **명세**다. 데이터화 대상이 아니다.

**빈칸 충전 방식(중력 낙하 vs 제자리 재추첨, 추첨 풀)은 미명시** — 99 「아직 결정할 항목」에 남아 있다.
**여러 저항체가 동시 정화될 때의 판정 순서도 미명시.**

### 2.6 판정 파이프라인 20단계 (확정 — 순서 변경 금지)

```
입력 잠금 → 최종 가중치 계산 → 초기 9칸 추첨 → 결과 공개 연출
→ 정상 영혼 기본 전력 → 저항체 개수 집계 → 개수 정화 → 직선 → 4연결
→ 가장 높은 유효 패턴 선택 → 승객·부품 사전 정화 효과 → 정화 대상 제거
→ 전력 계산 → 빈칸 재추첨 → 새 보드 재판정 → 캐스케이드 종료 조건
→ 잔류 계산 → 전력·상태 반영 → 결과 로그 → 입력 해제
```

⚠ **충돌**: 티켓 T-03의 데이터 주도 `EffectPipeline`은 효과를 전 구간에 분산시킨다.
08의 "절대 변경 금지"와 양립하지 않는다. → [DECISION_LOG.md](DECISION_LOG.md) C-08.

### 2.7 결정론 (확정)

- 전역 `UnityEngine.Random` **금지**. 명시적 시드 기반 RNG 서비스만 사용
- RNG 상태 = **런 시드 + 층 번호 + 스핀 번호 + 캐스케이드 번호** 조합
- **효과 RNG와 룰렛 RNG를 분리**한다
- 최종 가중치는 음수가 될 수 없다. 합이 0이면 **스핀 중단 + 명시적 오류**
- 디버그 패널에서 시드 직접 입력·재실행 가능
- 가중치 계산 7단계 순서: 심볼 기본 → 계약 보정 → 증식체 잔류 → 승객 → 부품 → 층 규칙 → 최소값 보정

### 2.8 판독 순서 (확정 — MASTER PRD §6.2)

시각 효과도 **이 순서대로 점등**한다.

1. 정상 영혼과 저항체 구분
2. 같은 저항체의 총개수
3. 기본 정화 발생
4. 직선 또는 연결 패턴
5. 제거 대상
6. 캐스케이드로 들어오는 신규 심볼
7. 승객·부품 발동
8. 전력 임계점과 위험 변화

> **한 화면에 모든 숫자를 동시에 띄우지 않는다.**
> 큰 배수 하나, 현재 캐스케이드 단계, 핵심 발동 원인만 우선 강조한다.

## 3. 계약

### 3.1 규칙 (확정)

- **층 시작 시 1회** 선택. 매 스핀 찍는 선택이 아니다
- 선택 전에는 레버를 사용할 수 없다
- 계약은 해당 층 전체에 적용된다
- **계약 변경은 허용하지 않는다**
- 선택 전에 예상 출현률·보상·잔류 대가를 공개한다

### 3.2 계약이 동시에 바꾸는 3요소 (확정)

1. 해당 저항체의 **등장 확률 증가**
2. 해당 저항체의 **정화 보상·패턴 배수 증가**
3. 정화하지 못했을 때의 **잔류 대가 증가**

### 3.3 초기 수치 (후보)

| 계약 | 가중치 | 정화 전력 | 잔류 대가 | 보상 축 |
|---|---|---|---|---|
| 흡수체 계약 | ×1.6 | ×1.5 | ×1.5 | **정화 전력** (개수 축) |
| 증식체 계약 | ×1.6 | ×1.35 | ×1.5 | **연결 패턴 보상** (배치 축) |

두 계약의 보상 축이 다른 것이 유일한 비대칭 설계 근거다.

## 4. 전력과 과수확

### 4.1 전력 종류 (확정)

`FloorPower` / `RequiredPower` / `StoredPower` / `ExcessPower`

### 4.2 요구 전력 (초기값)

```
RequiredPower = BaseFloorRequirement + WeightPenalty + FloorModifier
```
1층 기본 **80**, 층당 **+15**, 허용 중량 초과 1단위당 **+5**.

⚠ **충돌**: 티켓 T-04는 `기본 + 총무게 × 2`로 **초과분이 아니라 총무게**를 쓴다.
과적 설계의 전제가 달라진다. → [DECISION_LOG.md](DECISION_LOG.md) C-05.

### 4.3 🔴 2단 기계식 통합 레버 (확정 — 2026-08-02)

> 일반 실행과 과수확은 **하나의 크고 무거운 2단 기계식 레버**로 통합한다.
> 기존 문서의 별도 과수확 레버 문구는 이 결정으로 폐기한다.

| 상태 | 동작 |
|---|---|
| 요구 전력 미달 | 첫 번째 걸림점까지만 움직이며 **일반 스핀** 실행 |
| 요구 전력 100% 달성 | 내부 잠금쇠가 풀리고 **붉은 두 번째 구간** 노출 |
| 달성 후 | 첫 걸림점만으로는 스핀이 실행되지 **않는다**. 두 번째 걸림점을 넘어야 과수확 |
| 과수확 입력 | 약 **`0.7~1.0초` 유지 입력** + 강한 금속 걸쇠 피드백 |
| 안전 종료 | 레버와 **분리된** 전력 확정 브레이크 또는 확정 버튼 |
| 상태 문구 | 미달 시 `수확 실행` → 달성 후 `과수확 강행` |

> ⚠ **08 §15.2의 「길게 누르기 금지」와 정면 충돌한다.**
> MASTER PRD가 최상위이고 08 자신이 "충돌 시 MASTER PRD를 따른다"고 선언했으므로 MASTER PRD가 이긴다.
> **해소 규칙**: 일반 상호작용은 클릭 1회, **유지 입력은 과수확 2단 구간 단 하나의 예외.**
> 근거는 실수 방지다.

**활성 조건 (확정)**: `FloorPower >= RequiredPower` **그리고** 남은 스핀 ≥ 1.

### 4.4 "과수확"이라는 단어의 3중 사용 — ⚠ 명칭 분리 필요

| 출처 | 의미 | 발동 조건 |
|---|---|---|
| 참고 01 연쇄 단계 | 자동 진입 상태 | 5연쇄 도달 |
| 참고 01 전력 임계점 | 보너스 | 220% |
| **MASTER PRD §7 (확정)** | **플레이어의 명시적 선택** | 요구 전력 100% 후 2단 레버 유지 |

세 문서 어디에도 이 셋의 관계를 정의한 문장이 없다. **코드 명명에서 분리할 것.**

### 4.5 잔여 스핀 현금화 (확정 — 2026-08-02)

- 요구 전력을 남은 스핀이 있는 상태에서 달성하면 **안전 확정** vs **과수확** 중 선택
- 안전 확정 시 사용하지 않은 스핀은 **돈으로만** 변환한다
  (장치 수리·저장 전력·다음 층 요구 전력 감소·상점 새로고침 변환은 **제외**)
- 남은 스핀 1회당 지급액 = `RemainingSpinCashProfile.cashPerSpin`, 초기 프로토타입은 전 층 고정액
- 현금화는 캐스케이드·전력 임계점·승객/부품 재발동을 **발생시키지 않는다**
- **한 번이라도 과수확을 선택하면 그 층의 현금화 권리는 소멸한다**
- 안전 확정 기대값 목표: 추가 스핀 기대값의 약 **30~40%**
  ⚠ "추가 스핀 기대값"이 1회분인지 남은 전부인지 문서가 말하지 않아 두 해석이 3~4배 차이 난다

**선택 전에 반드시 표시할 정보 (확정)**
현재 전력과 요구 전력 / 남은 스핀과 즉시 획득할 돈 / 현재 캐스케이드 배수와 유지 여부 /
잔류 저항 대가 / 과수확 실패 시 예상 손실 범위 / 다음 초과 전력 임계점과 보상.

### 4.6 전력 임계점 (후보 — 원문이 "임시 기준")

| 임계 | 효과 |
|---|---|
| 100% | 정상 상승 확보 (**확정** — 과수확 해금선) |
| 130% | 추가 보상 |
| 170% | 추가 층 상승 |
| 220% | 과수확 보너스 |
| 300%↑ | 폭주 상승 |

⚠ 참고 00은 같은 자리에 `100 / 130 / 200%`를 적는다. 참고 01 표를 정본으로 본다.
⚠ 99 결정 로그는 "130% = 다층 상승"이라 적어 참고 01의 "170% = 추가 층 상승"과 어긋난다.

### 4.7 부분 성공 구간 (후보 — "플레이테스트로 조정한다")

| 달성률 | 결과 |
|---|---|
| 130%↑ | 다층 상승 또는 특수 보상 |
| 100~129% | 정상 상승 |
| 90~99% | 비상 상승과 장치 손상 |
| 70~89% | 승객·화물 포기 또는 큰 대가 |
| 70% 미만 | 추락·런 종료 위험 |

MASTER PRD는 부분 성공의 **존재만** 정의하고 비율은 정의하지 않는다. 충돌이 아니라 **빈칸을 채우는 유일한 후보**다.

## 5. 층 이동

### 5.1 1~10층 학습 곡선 (후보 — MASTER PRD 10층과 정확히 대응)

| 층 | 도입 |
|---|---|
| 1 | 자동 스핀과 정상 영혼 기본 수확 |
| 2 | 직선 패턴 보너스 |
| 3 | 4개 연결과 첫 캐스케이드 |
| 4 | 저항 계약 도입 (흡수체) |
| 5 | 승객·부품 선택과 휴식 |
| 6 | 증식체와 잔류 효과 |
| 7 | 계약 비교 (흡수체 vs 증식체) |
| 8 | 제한 스핀 + 적재 압박 |
| 9 | 푸시 유어 럭 |
| 10 | 종합 보스 계약 — **새 기본 규칙을 추가하지 않는다** |

> ⚠ 원본 커리큘럼의 "2층: 개수 정화 학습"은 인접 정화 전환으로 **교습 목표가 소멸**했다.
> 위 표는 그 반영본이다.

**층별 요구 전력의 절대값·증가 곡선, 층별 스핀 수는 Notion 전 문서 미명시.**

### 5.2 미해결 설계 공백

- **9층 「추가 스핀」이 5스핀 상한에 포함되는지 판정 불가** — 명시 필요
- 몬스터 효과 「남은 스핀 감소」의 **하한 규칙 없음** (5스핀에서 감소하면 실질 3~4스핀)

## 6. 이벤트와 위협

**프로토타입 처리 방식 (확정)**:
> 초기 프로토타입에서는 **별도 전투 화면 없이** 상태 효과, 심볼 풀, 계약과 선택 이벤트로 처리한다.

**몬스터 설계 대원칙 (확정)**: 체력을 깎는 적이 아니라 **룰렛과 계약을 오염시키는 사건**으로 사용한다.

**괴담 (확정)**: **완전한 문장 랜덤 생성 금지.** 검수된 사건 모듈을 조합한다.

**특수 숫자 층(444/666/777)은 10층 범위 밖** — 후속 승인 항목.
