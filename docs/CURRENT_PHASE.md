# 1. 세션 목표

기존 1층 Hero Slice와 결정론적 룰렛 코어를 **보존한 채**, 다음을 하나의 플레이 가능한
프로토타입 흐름으로 연결한다.

`계약 또는 위험 선택 → 실행 레버 → 3×3 결과 → 정화·패턴·캐스케이드 → 전력 →
확정 또는 과수확 → 상승 → 다음 층 → … → 10층 → 완주 또는 사고`

플레이어는 디버그 조작 없이 1층부터 10층까지 진행할 수 있어야 하며, 승객·부품이
룰렛 규칙과 위험을 실제로 바꿔야 한다.

# 2. 구현 대상

## 2.1 결정론적 코어 (Phase 1에서 완료 — 보존)

- 시드 기반 3×3 보드 생성
- 정상 영혼 1종 / 흡수체 / 증식체
- 흡수체 계약, 증식체 계약
- 같은 저항체 3개 이상 기본 정화
- 가로·세로·대각선 직선 3개 판정
- 직교 연결 4개 이상 판정
- 제거, 빈칸 충전, 재판정
- 캐스케이드 하드 캡 20회
- 흡수체 잔류 전력 감소 / 증식체 잔류 가중치 증가
- 전력과 요구 전력 판정
- 재현 가능한 `SpinResult`

**이 영역은 근거 없이 재작성하지 않는다.** 10층 연결에 필요한 최소 변경만 허용한다.

## 2.2 10층 진행 (이번 범위)

- 1층부터 10층까지 연속 진행
- 층 시작 계약 또는 위험 선택
- 층당 최대 스핀 수와 상승 조건
- 요구 전력 달성 후 전력 확정 또는 과수확 선택
- 다층 상승이 **최종 층과 빌드 보상 층을 건너뛰지 않음**
- 완주, 실패, 사고 결과가 정상 종료
- 고정 시드로 특정 층·스핀 단독 재현
- 진행 불가 상태 없음

## 2.3 승객·부품·적재 (이번 범위)

- 최소 4종 이상의 승객·부품
- 엘리베이터 안에 **실제 오브젝트로 배치** (메뉴 아이콘만으로는 불충족)
- 총중량, 허용 중량, 과적 상태
- 적재량이 요구 전력 또는 위험을 변경
- 승객·부품이 룰렛 확률·점수·정화·캐스케이드·잔류 위험 중 일부를 **실제로** 변경
- 최소 두 개의 명확히 다른 빌드 전략
- 승차·하차·획득·배치 흐름
- 최대 적재 상태에서도 이동과 장치 접근 가능

## 2.4 위험과 사고 (이번 범위)

- Stable / Warning / Critical / Collapse(Accident) 네 단계
- 조명·음향·진동·승객 반응이 상태에 따라 변화
- 과수확이 위험과 보상을 실제로 변경
- 사고 기록기가 실패 원인과 런 데이터를 정확히 표시

## 2.5 비주얼과 장치 (이번 범위)

- 좁고 높은 산업용 화물 엘리베이터
- PS1·초기 PS2 로우폴리 호러 방향
- 출입구 위 현재 층수 표시
- 세 통관과 3×3 결과판 대응
- 실행 레버와 과수확 레버 즉시 구분
- 과수확 잠금 구조가 물리적으로 이해 가능
- 세 심볼을 색상 없이 실루엣으로 구분
- 최대 적재 상태에서도 동선 유지

상세 기준은 `VISUAL_SPEC.md`와 `AUTONOMOUS_PROTOTYPE_GOAL.md` §4를 따른다.

# 5. 통과 게이트 — Phase 1 (이미 통과, 회귀 금지)

> 아래 Gate A~D는 **직전 Phase의 게이트**이며 커밋 `0125b92`에서 전부 통과 판정되었다.
> 이번 실행에서는 **회귀 방지선**으로만 사용한다. 이번 실행의 완료 기준은
> `AUTONOMOUS_PROTOTYPE_GOAL.md` §13의 `P2-Gate A~H`다.

## Phase1-Gate A — 코어

- Unity 씬 없이 핵심 판정 테스트가 통과한다.
- 동일 시드가 동일 결과를 재현한다.
- 캐스케이드가 20회를 초과하지 않는다.

## Phase1-Gate B — 플레이 흐름

- 계약 미선택 상태에서는 스핀할 수 없다.
- 레버 한 번으로 결과 공개와 판정이 완료된다.
- 중복 입력으로 상태가 손상되지 않는다.
- 요구 전력 달성 후 확정 또는 과수확을 선택할 수 있다.
- 디버그 조작 없이 층을 종료할 수 있다.

## Phase1-Gate C — 판독성과 위험

- 정상 영혼, 흡수체, 증식체를 1초 안에 구분할 수 있다.
- 정화와 캐스케이드 원인을 따라갈 수 있다.
- Stable과 Critical 상태가 무음 캡처에서도 구분된다.
- 과수확 레버가 일반 실행 레버와 혼동되지 않는다.

## Phase1-Gate D — 기술 증거

- 치명적 콘솔 오류가 없다.
- 테스트 결과와 재현 시드가 저장된다.
- 캡처와 성능 측정 결과가 제출된다.
- 미완료와 승인 대기 항목을 숨기지 않는다.

# 6. 중단 규칙

- 빌드가 깨진 상태에서 새 기능을 추가하지 않는다.
- 기존 EditMode/PlayMode 테스트가 깨진 상태에서 새 기능을 추가하지 않는다.
- 실패한 테스트를 삭제·무시·완화해 통과시키지 않는다.
- 동일 오류를 세 번 반복하면 최소 재현 테스트 또는 격리 전략으로 전환한다.
- 사용자 승인 없이 이 문서의 제외 항목을 현재 범위로 승격하지 않는다.
- 씬 또는 직렬화 에셋 손상이 의심되면 마지막 정상 커밋으로 복구한다.
- 승인 대기 항목(캐릭터·색·재질·모션·음향·밸런스·공포 강도)을 하나의 최종안으로 잠그지 않는다.
