## 1. 한 문장 정의 (확정)

> 1인칭으로 낡은 산업용 엘리베이터 안을 직접 돌아다니며 승객과 부품으로 영혼 수확 장치를 개조하고,
> 층마다 위험한 저항 계약을 선택한 뒤 자동 3×3 룰렛의 정화·패턴·캐스케이드를 거대한 전력 연쇄로
> 바꾸며 상승하는 **오컬트 호러 로그라이크**.

## 2. 핵심 판타지 (확정)

플레이어는 **조작자가 아니라 운영자**다.

> 빠른 반응으로 구슬을 멈추는 조작자가 아니다. 위험한 저항을 일부러 더 불러들이고,
> 확률·패턴·재발동 규칙을 설계한 뒤 큰 레버를 당겨 **자신이 만든 엔진이 폭발하는 것을 지켜보는** 운영자다.

이 한 문장이 폐기 결정 전부의 근거다 — 타이밍 정지, 구슬 이동, 연타·리듬은 전부 "조작자"의 것이라서 잘렸다.
자세한 폐기 목록은 §8과 [DECISION_LOG](DECISION_LOG.md).

## 3. 노스스타 (확정)

> 평범한 한 번의 레버 입력이 플레이어가 설계한 계약·승객·부품의 연쇄 발동을 통해
> **수초간 멈추지 않는 기계적·시청각적 폭주**로 변해야 한다.
> 동시에 플레이어와 관전자는 **무엇이 발동했고, 왜 이득이며, 지금 얼마나 위험한지**를 따라갈 수 있어야 한다.

뒷문장이 앞문장만큼 중요하다. 판독성은 폴리싱이 아니라 노스스타의 절반이다.

## 4. 감정 곡선 (확정)

```
낡고 불완전한 기계 → 불안한 첫 스핀 → 작은 정화 → 패턴 발견 → 자동 연쇄
→ 요구 전력 돌파 → 멈출 수 있는데도 과수확 선택 → 엘리베이터 전체가 붕괴 직전
→ 성공 또는 후회 → 상승과 반전 단서
```

## 5. 플레이어 경험 목표

### 5.1 반복 수행하는 기본 행동 (확정)

```
공간 탐색 → 오브젝트 확인·선택 → 레버 클릭 → 자동 판정 → 연쇄 관전 → 다음 선택
```

### 5.2 플레이어가 스스로 던져야 하는 질문 (확정 — 설계 검증 기준)

- 이번 층에서 어떤 저항 계약이 내 빌드와 가장 잘 맞는가?
- 높은 보상을 위해 더 위험한 저항 출현률을 감당할 것인가?
- 현재 심볼 풀은 직선, 연결 덩어리, 특정 위치 중 무엇을 잘 만드는가?
- 정화되지 않은 저항을 다음 스핀까지 남겨도 되는가?
- 현재 전력을 확정할 것인가, 배수와 오염을 안고 한 번 더 돌릴 것인가?

### 5.3 난이도의 원천 (확정 — 금지 규칙 포함)

> 상호작용의 난이도는 조준 정확도나 빠른 클릭이 아니라 **무엇을 선택하고 어떤 위험을 감당하는지**에서 발생한다.

**속도 증가와 짧은 타이밍 입력은 핵심 난이도 수단으로 사용하지 않는다.**
난이도 확장은 7축으로만 한다 — ① 요구 전력 증가 ② 제한 스핀 압박 ③ 저항체 종류 추가
④ 잔류 효과 강화 ⑤ 계약 보상·대가 확대 ⑥ 층 규칙 ⑦ 보스 계약.

## 6. 핵심 게임 루프 (확정 — MASTER PRD §5)

1. 층 도착
2. 요구 전력, 남은 스핀, 현재 적재량과 위험 확인
3. 흡수체 또는 증식체 **계약 선택** (층당 1회, 변경 불가)
4. 승객·부품 확인 및 선택
5. 큰 실행 레버를 클릭
6. 세 통관이 회전하고 9칸 결과를 **순차** 공개
7. 정상 영혼 기본 전력 획득
8. 저항체별 총개수 계산과 **인접 3개 이상** 정화
9. 직선과 4개 연결 판정
10. 제거, 빈칸 충전, 캐스케이드 재판정
11. 승객·부품·임계점 발동
12. 정화되지 않은 저항의 잔류 효과 적용
13. 요구 전력 미달이면 다음 스핀
14. 요구 전력 달성 시 **전력 확정 브레이크** 또는 **통합 레버의 과수확 구간** 선택
15. 상승, 부분 성공, 사고 또는 런 종료
16. 사고 기록기 출력 후 다음 층 또는 새 런

## 7. 프로젝트 범위

### 7.1 현재 버티컬 슬라이스 범위 (확정 — MASTER PRD §4.1)

| 항목 | 값 |
|---|---|
| 플랫폼 | Unity 6000.5.5f1 / URP 17.5.0 / Windows PC |
| 층 | **10층** |
| 스핀 | 한 층 최대 **5회** |
| 룰렛 | 세 통관 × 각 3결과 = **3×3** 자동 |
| 심볼 | 정상 영혼 **1종** + 저항체 **2종**(흡수체·증식체) |
| 계약 | **2종** (흡수체 계약 / 증식체 계약) |
| 승객·부품 | **최소 4종** (§7.3 참조) |
| 캐스케이드 | 하드 캡 **20회** |
| 위험 | 4단계 `Stable → Strain → Critical → Collapse` |

그 외 필수: 1인칭 이동·마우스 시점 / 인접 3개 이상 정화 / 직선 3개 보너스 /
4개 이상 직교 연결 제거 + 캐스케이드 / 잔류 효과 / 전력·요구 전력·초과 임계점 /
**2단 통합 레버 + 전력 확정 브레이크** / 과적과 요구 전력 증가 / 감각적 위험 상태 /
승객 상황 반응 / 사고 기록기 / 디버그 패널·결정론적 시드·텔레메트리.

### 7.2 명시적 제외 (확정 — MASTER PRD §4.2)

통관별 정지 버튼과 타이밍 정지 / 구슬 위치 이동·교환 / 연타·리듬·정밀 클릭 /
L·T·십자·고리 특수 패턴 / 정상 영혼 9종 등급 체계 / 추가 저항체 /
완성형 멀티 엔딩 / 완성형 대화·관계도 / 온라인·멀티플레이·Twitch 연동 /
최종 캐릭터 아트와 애니메이션 / 최종 수치 밸런스 / 장기 메타 진행과 세이브 슬롯.

> ⚠ **L·T·십자·고리는 폐기가 아니라 범위 밖이다.** 정식 설계로 살아 있고 업그레이드 해금이
> 예정돼 있다. 지금 구현하면 폐기 위반이 아니라 범위 이탈이다.
> 프로토타입이 인정하는 패턴은 **직선 3개**와 **4개 이상 직교 연결** 둘뿐이다.

### 7.3 "최소 4종"의 해석 — 미확정, 가정으로 진행

MASTER PRD §4.1은 `승객·부품 최소 4종`이라고만 적고 **어떤 4종인지 어디에도 명시하지 않았다.**
수량이 나오는 세 곳이 서로 다르다:

| 출처 | 값 |
|---|---|
| MASTER PRD §4.1 | 승객·부품 최소 4종 (하한) |
| 핵심 개편 (2026-08-03, 확정 콜아웃) | 승객 **7명** + 장착 아이템 **8종**, 동시 탑승 4 / 활성 아이템 3 |
| 확장 설계 09 태그절 | 승객 4~5종 (태그 검증용 축소 범위) |

**채택 기준**: 핵심 개편의 「핵심 공명 시나리오 4개」가 프로토타입이 증명해야 할 것이다.
자세한 것은 [PASSENGER_SYSTEM.md](PASSENGER_SYSTEM.md) §5.

## 8. 하지 않을 것 (되살리면 안 되는 것)

구현자가 코드에서 식별할 수 있는 형태로 적는다. 전체 목록과 근거는 [DECISION_LOG.md](DECISION_LOG.md).

| 폐기 | 코드에서 이렇게 보이면 위반 |
|---|---|
| 통관별 정지 버튼 | `StopReel(index)`, 릴별 개별 정지 상태 |
| 실시간 타이밍 정지 | 입력 시각 → 결과 매핑, `Time.time` 기반 정지 판정 |
| 수동 구슬 이동·교환 | `SwapCells`, `MoveSymbol`, 매치3식 인접 교환 |
| 2매치 긴급 배출 | `if (count == 2) EmergencyEject()` — 단, *업그레이드 효과*로는 정상 |
| 9종 × 4등급 | 심볼 enum 9종, `Rarity{Common,...}` |
| 통관 증설 성장축 | 릴 개수 가변, 보드 크기 확장 업그레이드 |
| 세트 보너스 UI | `2/4` 카운터, 초상화 아래 직업 태그 뱃지 |
| 승객 대기석·벤치 | 비활성 승객 리스트, 예비 슬롯 배열 |
| 사전 빌드 선택 | 런 시작 전 계열 선택, 출현 명부 등록 |
| 위치 무관 개수 정화 | 인접 검사 없는 `CountOf(kind) >= 3` 단독 판정 |

**용어 함정**: `Marble` / `Ball` / `Bead` 라는 이름이 코드·에셋에 있으면 구설계 유입 신호다.
현행 정식 용어는 **정상 영혼 / 저항체 / 심볼**이다.

## 9. 최종 의사결정 원칙

### 9.1 문서 우선순위 (Notion MASTER PRD §1.1이 자기 선언)

1. **MASTER PRD**
2. 기술 부록 08 (Unity 구조·테스트 명세)
3. 분야별 참고 원본 (00 비전 / 01 룰렛 / 02 빌드 / 03 층 / 04 NPC / 05 스포일러 / 06·07 비주얼)
4. 99 결정 로그 — 결정 기록과 체크리스트 용도
5. **아카이브와 폐기 아이디어는 구현 근거로 사용하지 않는다**

### 9.2 충돌 해소 규칙

1. 사용자가 가장 최근에 명시적으로 확정한 결정
2. 상태가 확정/Approved/Final로 표시된 내용
3. 최근 작성된 구체적 시스템 명세
4. 핵심 목표와 일치하는 내용
5. 오래된 브레인스토밍·후보 아이디어

> 페이지 수정 날짜만 보고 최신 결정이라 판단하지 않는다. **본문의 결정 상태와 맥락을 함께 본다.**

### 9.3 AI 작업 원칙 (MASTER PRD §1.2)

- 명백한 구현 세부사항은 합리적으로 결정하고 진행한다.
- **밸런스, 캐릭터 최종 디자인, 최종 모션, 최종 색·재질, 공포 표현 강도는 임의로 잠그지 않는다.**
- 승인 대기 요소는 플레이스홀더와 **2~3개 교체 가능한 프리셋**으로 구현한다.
- 모든 가변 요소는 데이터 또는 프로파일로 분리한다.
- 불명확해도 작업을 중단하지 않는다. 안전한 기본값 + `ASSUMPTION_LOG` 기록.
- **새 핵심 시스템을 추가하지 않는다.** 현재 코어 루프의 이해도·긴장·반복성부터 검증한다.
- **구현 에이전트가 자신의 결과를 스스로 통과시키지 않는다.**

## 10. 서사 제약 — 프로토타입 UI에 직접 영향

세계관의 진실(악신의 세계 수확 장치, 저항체 = 자아를 유지한 생존 의식)은 **전면 노출 금지**다.

**중립 어휘 규칙 (확정)** — 초중반 UI·대사·에셋 명칭에서:

| 쓴다 ✅ | 쓰지 않는다 🔴 |
|---|---|
| 전력, 출력 | 영혼, 수확 |
| 불량체, 오염 | 저항체(플레이어 노출 시), 자아 |
| 정화, 계약 | 소거, 표적 수확 |

코드 내부 명칭은 자유다. **플레이어에게 보이는 문자열만** 이 규칙을 따른다.

**프로토타입에서 허용되는 반전 암시 5개** (전부 중립 어휘를 유지한 채 연출만으로 성립):

1. 상승 후 문 밖의 식물과 빛이 약해짐
2. 떠난 층의 조명이 꺼짐
3. NPC가 '수확량'이라고 말한 뒤 **'출력'으로 정정**
4. 적대 존재가 플레이어보다 **발전기를 집중 공격**
5. 돈과 전력의 재질에서 얼굴·눈·목소리 같은 흔적

저항체 시각 표현은 **초반 층위만** 사용한다 — 검은 찌꺼기·오염물·결함 심볼.
(중반의 "내부에 심장·눈·뼈", 후반의 "인간 실루엣과 공통 기억"은 프로토타입 범위 밖.)
